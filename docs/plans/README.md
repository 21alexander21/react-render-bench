# Implementation plans

Implementation plans are temporary execution artifacts for work that is too complex to track safely in one issue description.

## Locations

- `active`: approved plans that are currently actionable.
- `archive`: completed or superseded plans kept for historical context.

Create the `active` directory only when the first active plan is needed. Do not keep empty placeholder directories.

## Rules

- Use GitHub Issues for ordinary tasks.
- Do not create a plan for a small or obvious change.
- Link an active plan to its issue or milestone when a remote repository exists.
- Keep steps atomic, ordered, and independently verifiable.
- State affected files, constraints, and completion evidence.
- Do not duplicate the roadmap or issue backlog in a plan.
- Move a completed plan to `archive` and record its status and completion date.
- Update or archive stale plans instead of allowing them to remain misleading.
